# Code Review Reports

This directory contains AI-powered code review reports generated by the `code-reviewer` agent.

## Overview

The code-reviewer agent performs comprehensive, intelligent code analysis using Claude Opus with deep analysis capabilities. Reports are automatically saved here when reviews are conducted.

## Report Naming Convention

Reports are named using the pattern:
```
review-[timestamp].md
```

Example: `review-2025-11-18-140523.md`

## Report Structure

Each review report includes:

1. **Executive Summary** - Overall assessment and statistics
2. **Critical Issues** - Must-fix items (security, data loss, crashes)
3. **High Priority Issues** - Should fix before merge
4. **Medium Priority Issues** - Should fix soon
5. **Low Priority Issues** - Nice to fix
6. **Informational Suggestions** - Learning opportunities
7. **Code Metrics** - Complexity analysis and statistics
8. **Architecture Review** - Design patterns and SOLID principles
9. **Performance Observations** - Performance issues and optimizations
10. **Security Review** - Security checklist and vulnerabilities
11. **Testing & Testability** - Test coverage and testability assessment
12. **Language-Specific Review** - Best practices for the language
13. **Positive Highlights** - Good practices observed
14. **Prioritized Action Items** - What to fix and when
15. **Learning Resources** - Educational materials
16. **Review Comparison** - Trends vs. previous reviews
17. **Conclusion** - Final recommendations

## Integration

The code-reviewer agent integrates with the orchestration workflow:

```
1. coder implements feature
2. code-reviewer analyzes implementation
3. If issues found → stuck agent (human decides)
4. If clean → tester verifies functionality
5. Mark todo complete
```

## Severity Levels

- **CRITICAL** - Must fix immediately (security, data loss, crashes)
- **HIGH** - Should fix before merge (code smells, best practices)
- **MEDIUM** - Should fix soon (readability, documentation)
- **LOW** - Nice to fix (naming, organization)
- **INFO** - Informational (learning, alternatives)

## Best Practices

1. **Review Early** - Run reviews during development, not just before merge
2. **Act on Critical Issues** - Address critical/high issues immediately
3. **Learn from Reviews** - Use reviews as learning opportunities
4. **Track Trends** - Monitor metrics to see code quality improvements
5. **Configure Wisely** - Adjust thresholds based on project needs
6. **Don't Ignore** - Every issue is flagged for a reason

## Example Review Invocation

As orchestrator, invoke the code-reviewer like this:

```javascript
// After coder completes implementation
const coderResult = await invokeAgent('coder', 'Implement user authentication');

// Review the implementation
const reviewResult = await invokeAgent('code-reviewer',
  'Review the authentication implementation in src/auth/*'
);

// If critical issues found
if (reviewResult.hasCriticalIssues) {
  const decision = await invokeAgent('stuck',
    'Critical security issues found in auth: ' + reviewResult.issues
  );
}

// Otherwise continue to testing
const testResult = await invokeAgent('tester',
  'Test the authentication flow'
);
```
